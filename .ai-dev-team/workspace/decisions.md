# Decisions

D1 (confirm-on-return, 19:15) — Q: "Cài thông qua repo" can mean an apt repository (PPA) or installing from this git repository. Choice: install from the git repository with a user-level script (`./install.sh`: cargo build --release, install to ~/.local, systemd user unit, gsettings); uninstall with `./uninstall.sh`. A .deb/PPA can be added later without changing the code. Why: cheaper, reversible, needs no sudo while the user is away.
D2 (19:15) — Q: may tests touch the live desktop (the user's running fcitx5, input sources)? Choice: no. Automated tests run in a nested/headless GNOME Shell session with its own D-Bus bus and XDG dirs; the live desktop is never changed until the user returns. Why: narrowest option; the user's fcitx5 keeps working.
D3 (19:15) — Toggle key is Ctrl+Shift tapped alone (press both modifiers, release with no other key between); Ctrl+Shift+<key> shortcuts keep working. Source: user.
D4 (19:15) — Install applies immediately: no logout, no reboot. Apps opened after install get the IME; X11 apps already open (Chrome, VS Code under XWayland) may need one restart of that app — proven or refuted by spike T1. Source: user (hot apply), leader (app restart caveat).
D5 (19:15) — Typing method: standard Telex only (user corrected "talex" to Telex). Modern tone placement (hoà, thuý). Source: user + leader defaults stated in chat, not objected.

Answers to the builder check (leader, user away; facts from this machine):
- Fact F1: on GNOME Wayland the only IBus client is gnome-shell itself (`IBus.Bus.new_async()` in misc/ibusManager.js; it connects via the IBus address file `~/.config/ibus/bus/<machine-id>-unix-<display>`, spawns `ibus-daemon` only if it exists, and requests the panel name `org.freedesktop.IBus.Panel` on that bus). So the IBus side is a private mini D-Bus bus (Hello, RequestName, AddMatch, NameOwnerChanged, routing to the panel) plus the IBus service/engine/input-context objects.
- Fact F2: this machine runs gnome-shell with `GTK_IM_MODULE=fcitx QT_IM_MODULE=fcitx XMODIFIERS=@im=fcitx SDL_IM_MODULE=fcitx` (im-config `run_im fcitx5`). Every app launched from the shell inherits that until the next login, so GTK3 apps (gnome-terminal, Chrome/VS Code under XWayland) load the fcitx IM module and talk the fcitx5 D-Bus frontend (`org.fcitx.Fcitx5` / `org.freedesktop.portal.Fcitx`), not IBus or XIM.
D6 (19:40) — Toggle detection is engine-only: the daemon sees Ctrl/Shift only through the key events clients forward (IBus, fcitx, XIM). The VI/EN state is global (one state for all contexts, persisted by the daemon); with no focused text field there is nothing to toggle for. No shell extension, no evdev. The indicator is the native GNOME one: a single source `('ibus','vr-talex')` whose `InputMode` property shows `VI`/`EN`. AC-4's 100 ms applies with a focused field.
D7 (19:40) — "Tapped alone": toggle fires on release of the last of Ctrl/Shift when both were down together, in either order, no other key pressed or released in between, both held < 1 s. All modifier events are returned unhandled (passed to the app), so Ctrl+Shift+<key> always reaches the app.
D8 (19:40) — Frontends: (1) IBus protocol on a private bus — serves gnome-shell (Wayland text-input-v3 apps, the indicator); (2) fcitx5 D-Bus frontend protocol on the session bus (`org.fcitx.Fcitx5`, `org.freedesktop.portal.Fcitx`) — serves apps already started with `GTK_IM_MODULE=fcitx` (F2), which is what makes hot apply work on machines that used fcitx5; (3) XIM server — only for X11 apps whose toolkit uses XIM; built last and dropped if spike T1 shows Chrome/VS Code never take that route here. Spike T1 decides the final list from measurements; the plan holds tasks for all three.
D9 (19:40) — Hot-apply fallback: if T1 proves gnome-shell cannot be reached without restarting it (Wayland = logout), AC-5 becomes "works without logout in every app that uses the fcitx or XIM route and in new apps; the GNOME indicator and Wayland-native-only apps start working at next login", and the installer says so. (confirm-on-return)
D10 (19:40) — No-preedit clients: always preedit when the client declares the preedit capability (VTE/gnome-terminal, GTK, Chrome do). Without it: commit + DeleteSurroundingText only when the client declares surrounding-text support; otherwise the word is held and committed at the boundary. Fake BackSpace never.
D11 (19:40) — Installer footprint (all user-level, every changed file backed up to `~/.local/share/vr-talex/backup/` first): `~/.local/bin/vr-talex`, `~/.config/systemd/user/vr-talex.service`, `~/.config/environment.d/90-vr-talex.conf` (IM vars for next logins), `~/.xinputrc` via `im-config -n none` equivalent written directly, `~/.config/autostart/org.fcitx.Fcitx5.desktop` with `Hidden=true`, gsettings `org.gnome.desktop.input-sources sources/mru-sources`. The running fcitx5 is asked to quit cleanly (`fcitx5-remote -e`, or `systemctl --user stop` when it is a unit), never killed by name. Uninstall restores the backups and starts fcitx5 again when it was the previous framework.
D12 (19:40) — AC-2 automation: a headless nested GNOME Shell 46 (`gnome-shell --headless --wayland --virtual-monitor`, own D-Bus session and XDG dirs, D2) with keys injected through Mutter's RemoteDesktop D-Bus API (real compositor path, no privileges). Text read back: Chrome via DevTools protocol on a throwaway profile, VS Code via a saved file in a throwaway `--user-data-dir`, gnome-terminal via `cat > file`. Plus one manual run by the user on the real desktop on return (listed in the report).
D14 (user, 19:36; replaces the leader's earlier "keep GPL dictionary data") — No dictionary anywhere: the golden list is generated from rules only; the engine has no word list and no spelling correction — the user must type correctly. Source: user ("Làm đơn giản nhất, không cần từ điển, người dùng buộc gõ đúng, không cần sửa chính tả").
D15 (user, 19:37) — Keep raw-key restore for non-Vietnamese words (`class`, `windows` stay as typed in VI mode), decided by structural syllable rules only, no dictionary. Source: user answer "Giữ trả chữ gốc".
D16 (19:52, leader; T3 review findings 1–2) — The c/ch/p/t-final tone restriction is NOT used to mark a word invalid: an untoned or z-cleared word (`bât`, `viêt`) is a word still being typed, and restoring raw keys there would break `baat` + `j` → `bật`. A missing tone never makes a word invalid. A wrong tone on a stop final (huyền/hỏi/ngã on c/ch/p/t, e.g. `bacr`) does → raw keys, as T2 built and the golden list expects; validity for raw-restore (D15) is otherwise decided by letters (initial, nucleus, final). No spelling correction (D14). Golden cases `baat>bât`, `vieetjz>viêt` stay. Review finding 1 rejected, finding 2 resolved by this; finding 3 fixed in README by the leader (doc line).
D17 (19:52, leader; T2 interpretations) — Accepted as known limits, listed in the report: `uow` → `ươ` always (`thuở`, `huơ` cannot be typed); aa/ee/oo transform only when adjacent; undo-by-repeat then more letters keeps raw keys (`xoong` cannot be typed). Why: simplest rules, user asked for simplest (D14).
D13 (19:40) — Tone placement: modern convention. Tone on the vowel with a diacritic (â ă ê ô ơ ư; on ơ for ươ, on ê for iê/yê/uyê); oa/oe/uy → second vowel (hoà, khoẻ, thuý); ia/ua/ưa (no final consonant) → first (mía, múa, mưa); u after q and i after g are consonant parts (quý, giá) unless no other vowel (gì, gìn). The golden list is built from a public Vietnamese syllable list by a qc agent with its own reverse function (word → Telex keys), never by the engine's author.
