# Review E1 — word lists

Tools available: Read, Bash, Write, Skill, SendMessage, SubagentHandback.

Verdict: **FAIL (CHANGES_REQUESTED)**. Format, licences, size, reproducibility and SEC-2 are fine. vi.txt lacks real, engine-typeable Vietnamese syllables, including very common ones (nghĩa, giống, giọng, giúp, giỏi, giọt).

## Findings

[high] tools/golden-gen/gen.py:131-143 (shape tables used by tools/wordlists/gen.py:authored_syllables/source_syllables) — real syllables missing from crates/telex-core/data/vi.txt
Scenario: the engine types `nghiax` → `nghĩa`, `giups` → `giúp`, `gioongs` → `giống`, `giongj` → `giọng`, `gioir` → `giỏi`, `giojt` → `giọt`, but none of these (nor any tone of them) is in vi.txt (grep -x confirmed). Under AC-1 the E2 completeness check treats an uncomplete/unknown syllable as raw, so the user typing Vietnamese `nghĩa` (383 occurrences in the reference list, the most frequent missing syllable), `giống`, `giọng`, `giúp`, `giỏi` gets `nghiax`, `gioongs`... at word end. This is the exact failure the list exists to prevent.
Root cause: the GI table (`"u": ["", "c"]`, `"o": ["", "n"]`, no `ô`, no `oi`, `ơ` only `["", "n"]`, ...) and `GH_OK` (no `ia`, `êu`, `iu`) are too narrow; gen.py only keeps reference syllables whose shape exists in `base_syllables()`, so the reference list could not add them either. The same tables miss other shapes (counts from the reference list, tokens absent from vi.txt):
- gi+: giống 52, giọng 42, giọt 30, giỗ 20, giúp 17, gióng 14, giẻ 13, giập 11, giỏi 10, giăm 10, giong 10, giũa 9, giùi 9, giông 9, giun 31, giòi, giẹp, giền, giội, giúi, giô, giối, giếc, giấp, giuộc, giùm, giặm, gièm, giồng
- ngh+: nghĩa 383, nghễu, nghêu, nghều, nghỉu, nghịu, nghểu
- qu+: quặm, quăm, quắm, quạu, quều, quệt, quết, quýu, quằm
- ng+oa+m / kh+oă+m: ngoạm, ngoàm, ngoằm, khoằm, khoăm, hoắm
- ư+i after c/ch-like initials: cửi (10)
Not-bugs: hòa/hóa/hỏa/thủy/tùy/khỏe are absent only because the engine types the old placement (hoà, thuỷ, khoẻ are present); thuở/huơ/khuơ cannot be typed (`thuowr` → `thưở`, which is in vi.txt) — an engine matter for E2, not E1.
Fix: widen the GI table to {u: ["", "c", "n", "p"], o: ["", "n", "i", "ng"], ô: ["", "ng", "i", "c"], ơ..., ia, ua...}, add `ia`, `êu`, `iu` to GH_OK for ngh, add `ă`/`oa`/`êu` finals to QU and the `oa`/`oă` + `m` shapes for ng/kh, add `ưi` to the c-like initial set, or (simpler) let gen.py accept every reference token whose NFC text the engine reproduces from `reverse_keys`, instead of filtering by the shape table. Regenerate, then re-run the spot check (nghĩa, giúp, giống, giọng, giỏi, giọt, giỗ, giun, nghêu, cửi must be present).

[minor] crates/telex-core/data/vi.txt — over-inclusion
The authored table is deliberately inclusive: it holds non-words such as `bỉe`-like shapes and `tó/cõ/tũ/lĩ` (tones of real syllables that exist only in a few words). Low impact (an English word whose form is one of these would be read as Vietnamese). No action required.

[minor] tools/wordlists/vi_overrides.py — marginal exclusions
Of the 652 distinct forms produced by en.txt words and absent from vi.txt, I judged all but a few as non-syllables. Marginal and attested only in loan words or dialect: `tỏn` (tỏn tẻn), `pít`, `péc`, `pét`. Excluding them is acceptable; no real common syllable is wrongly excluded by the overrides. Full list: qa-artifacts/E1-review/notin.txt.
