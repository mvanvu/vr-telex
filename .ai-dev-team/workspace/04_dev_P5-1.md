## Root causes
- corr #1: `pop_letter` (lib.rs) always called `resync_raw`, which rewrites `raw` as canonical keys (letters, tone key last, overridden tone keys dropped); `finish` restores and looks up `raw`, so `usern<` committed `uer`, and `moren<` looked up `moer` (not in en.txt) and kept `moẻ`.
- corr #2: `finish`, text == keys branch, returned `prev` for every word outside en_plain (D7), so `cho`/`anh` kept an En run alive.
- corr #4: `finish` returned the shown text for every non-Viet mode; a tone-key undo (`pass` → `pas`, Mode::Undone) never consulted en.txt.
- sec #2: `parse` built a `Vec<char>` and two `String`s from the typed letters per call and dropped them unwiped; same for the `render_to`/`horn` nucleus `Vec<char>`, `try_letters` rejected trials, and the Raw-mode `pop` key copy.

- security minor (SEC-4): fixed.
  - `Composer::new` sizes raw and text at `WORD_BYTES` (32 keys × 4 bytes) and letters at `WORD_KEYS` (32, = ime-core MAX_WORD_KEYS); so neither the main composer nor the BackSpace replay composer reallocates within a word of up to 32 keys.
  - `try_letters` copies the valid trial into the composer's own buffer (it used to swap in the clone and lose the capacity).
  - Key copies use `typed_keys()` (`Vec::with_capacity(raw.len())` + extend, so the collect cannot grow).
  - The temporary `before`/`shown` strings get the same capacity.
  - The `horn` undo rotates the dropped letter to the end and blanks it, instead of `remove`, so no stale copy stays past `len`.
  - Every wipe now ends with `std::hint::black_box`: `wipe_letters` (clear, enter_passthrough, try_letters), `wipe_chars` (the three key copies) and `wipe_string`.
  - Test: lib.rs unit test `word_buffers_never_reallocate` checks the capacities after every key and every BackSpace for 8 words of up to 32 keys (`nghieeengs`, `usern`, `tuow`, 32 letters, 32 × `đ`). With the old `String::new()` it would fail on the first key.
