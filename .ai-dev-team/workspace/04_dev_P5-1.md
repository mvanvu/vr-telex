## b. build.sh trusts the pool on gh-pages (security, CWE-345): fixed
- tools/apt-repo/build.sh checks the following before it writes anything:
  - The pinned key is `APT_PINNED_KEY` or, by default, `packaging/apt/vr-telex.asc` relative to the script (the release checkout,
    never the site). It is dearmored into a temp gpgv keyring. Why this choice: with the default inside the script, release.yml needs
    no setting and cannot point it at the site by mistake. Tests set APT_PINNED_KEY to their throwaway key. ci-static-check asserts
    that the publish job sets neither APT_PINNED_KEY nor APT_REPO_BOOTSTRAP. Verified: a run without APT_PINNED_KEY resolves to
    `tools/apt-repo/../../packaging/apt/vr-telex.asc` (a throwaway signing key was refused with "is not the pinned key").
  - APT_GPG_KEY must be the pinned key (otherwise the next release would refuse the site this one signs).
  - `dists/stable/InRelease`, if present, must be a regular file and `gpgv --keyring <pinned> --output` must succeed. The SHA256 of
    `main/binary-amd64/Packages` in the verified text must match a copy of Packages, and that copy is the one parsed.
  - Every entry under pool/ (find, any name, any depth): symlinks and non-regular files are refused. Each file must be listed in
    Packages (Filename) with the same SHA256. The only exception is an input of this run at its own pool path with identical bytes.
  - A non-empty pool without InRelease is refused unless `APT_REPO_BOOTSTRAP=1` (the workflow never sets it).
  - dists/ or dists/stable as a symlink is refused. dists/stable is rebuilt from scratch (removed, then written), so a file planted
    under dists/ is no longer hashed into the signed Release (extra hardening for the same finding).
- New checks in tests/apt/run.sh (9 FAIL on the old build.sh; all pass now):
  - a vr-telex_9.9.9-1 planted in the pool is refused, site unchanged: `pool/main/v/vr-telex/vr-telex_9.9.9-1_amd64.deb: not listed in the signed index (dists/stable/InRelease); remove it from the site`
  - a file of any name and depth: `pool/main/x/evil/notes.txt: not listed in the signed index ...`
  - content swapped under a listed name, site unchanged: `pool/main/v/vr-telex/vr-telex_0.0.0~test-1_amd64.deb: does not match the signed index (SHA256 differs); refusing`
  - a symlink in the pool: `... not a regular file (symlink) in the pool; refusing`
  - Packages regenerated to list the planted file: `dists/stable/main/binary-amd64/Packages does not match the signed InRelease; refusing`
  - InRelease re-signed with another key: `dists/stable/InRelease does not verify with the pinned key ...; refusing to sign this pool`
  - a non-empty pool without InRelease: `... there is no signed InRelease to check it against; refusing (APT_REPO_BOOTSTRAP=1 signs it anyway)`
  - APT_REPO_BOOTSTRAP=1 on a copy of the site: accepted, logs `bootstrap: signing unchecked ...`
  - an extra file under dists/stable/main/binary-i386: gone after a rerun, not in Release
  - a signing key that is not pinned: `the signing key <fpr> is not the pinned key (...)`, site unchanged
  - after the site is restored, it takes the next version.
- release.yml publish job installs gpgv.
