# Threat model: vr-talex (Rust Telex IME daemon, IBus D-Bus impersonation + XIM server)

Inputs: `01_spec.md`, `decisions.md` (D1–D5). Greenfield; no code yet. Task IDs are not assigned yet: each threat names the component that owns the fix
(`core` daemon process, `ibus` private-bus server, `xim` XIM server, `engine` Telex state machine, `install`, `uninstall`, `unit` systemd user unit, `build` Cargo/CI, `test` harness).

## Assets
- A1 Every keystroke of the user, including passwords, PINs, the GNOME lock-screen password, chat and code (confidentiality is the main asset).
- A2 Preedit / composed text and IBus SurroundingText (text around the cursor that clients send to the IME).
- A3 Integrity of what reaches each app: text committed to the right window only, once, in order (a wrong-window commit is a data leak).
- A4 Availability of typing: if vr-talex breaks, the user must still be able to type (including unlocking the screen).
- A5 The user's desktop configuration: `org.gnome.desktop.input-sources`, fcitx5/ibus autostart, IM environment, shell rc files.
- A6 The build: crates pulled from crates.io and compiled into a process that sees A1.

## Trust boundaries and data flows
| # | Flow | Boundary |
|---|------|----------|
| F1 | Mutter/gnome-shell → IBus private bus (unix socket) → daemon: `CreateInputContext`, `ProcessKeyEvent`, `SetContentType`, `SetSurroundingText`, focus/reset; daemon → client: `CommitText`, `UpdatePreeditText`, `ForwardKeyEvent` | Socket file + address file under the user's home / runtime dir; any process that can open the socket can talk to the daemon |
| F2 | GTK/Qt apps with `GTK_IM_MODULE=ibus` (their own libibus) → same private bus | Same as F1; includes sandboxed apps if the socket is reachable |
| F3 | X11/XWayland clients (Chrome, VS Code, Electron) → X server → XIM protocol (ClientMessage / properties) → daemon | Any X client on the display, including Flatpak/snap apps with X11 access; XIM messages are attacker-controlled bytes |
| F4 | gnome-shell panel connection (input-source indicator VI/EN, `org.freedesktop.IBus.Panel`) | Same bus as F1 |
| F5 | Daemon → disk: mode state (VI/EN), logs (journald via stderr), crash dumps (apport / systemd-coredump) | Files readable by the user, other admins, bug reports sent to Canonical |
| F6 | `install.sh` / `uninstall.sh` → gsettings, `~/.config`, `~/.local`, `systemctl --user`, fcitx5/ibus | Script runs with the user's full rights; inputs are the git checkout and existing user config |
| F7 | crates.io → `cargo build` → binary | Third-party code executing in the keystroke process and at build time (`build.rs`, proc macros) |

| F1/F3 | Unbounded connections, ICs, preedit length, surrounding-text size | D | Medium | Medium | SEC-16 → ibus, xim, engine |
| A4 | Daemon crash or hang leaves the user unable to type (incl. lock-screen unlock); stale address file points to a dead socket | D | Medium | Critical | SEC-17, SEC-18, SEC-19 → core, unit, install |
| A3 | Commit goes to the wrong IC after focus change (text of one window typed into another) | I/T | Medium | High | SEC-9, SEC-13 → engine, ibus |
| F6 | Script run with sudo / as root, writes root's config or root-owned files in the user's home | E/T | Medium | High | SEC-20 → install |
| F6 | Non-idempotent install overwrites the saved backup with already-modified state, so uninstall cannot restore (A5 lost) | T | High (run twice is an AC) | High | SEC-21, SEC-22 → install, uninstall |
| F6 | Unquoted variables / `rm -rf "$X/"` with empty X / broad `pkill -f` / blind edits of `~/.profile` | T/D | Medium | High | SEC-23 → install, uninstall |
| F6 | `curl | bash`, downloading rustup/tools or binaries at install time | T | Low | Critical | SEC-24 → install |
| F7 | Vulnerable, yanked, typosquatted or git-sourced crate; `build.rs` with network/file side effects; unpinned versions | T/I | Medium | Critical (code in a keylogger-capable process) | SEC-25, SEC-26 → build |
| F7 | `unsafe` code in our crates (prctl, mlock, X11 parsing) causing memory corruption reachable from F3 | T/E | Medium | High | SEC-27 → build, core |
| F1–F7 | Network egress (telemetry, update checks) of a process that sees keystrokes | I | Low | Critical | SEC-28 → core, unit |
| D2 | Automated tests touch the live desktop (user's fcitx5, input sources, real keystrokes) | T | Medium | Medium | SEC-29 → test |

## Automated abuse
Not applicable: no public network flow (no HTTP endpoint, no API, no account). Local abuse by other processes is covered by SEC-6…SEC-16.

## Security requirements for implementation

Each requirement: threat → requirement → how to verify.

- **SEC-1 No typed text in any output.** Threat: daemon becomes a keylogger (anti-goal, AC-9). Requirement: no log, `eprintln!`, `tracing`/`log` call, panic message, error string or file write includes key symbols, keycodes of printable keys, preedit, commit text, surrounding text or Telex buffers. Allowed in logs: event kind, IC id, counts, lengths, timings, mode VI/EN. No runtime flag, env var or cargo feature (incl. `debug`) enables key logging in any build. Verify: reviewer greps every log/format macro for text-carrying identifiers; qc runs the §6 stress test in the nested session with log level at maximum (`RUST_LOG=trace` or equivalent), then greps journal (`journalctl --user -u vr-talex`), stderr capture and `~/.local/state/vr-talex`, `~/.cache`, `/tmp`, `$XDG_RUNTIME_DIR` for ≥ 20 distinctive typed words (e.g. `zqxjkvietnam42`) and their composed forms → 0 hits.
- **SEC-2 Redacting types for text.** Threat: `{:?}` of a struct leaks text in a panic or error. Requirement: all text-holding values (key buffer, preedit, commit, surrounding text) are wrapped in a newtype whose `Debug` and `Display` print `<redacted len=N>`; structs containing them do not derive a leaking `Debug`. `unwrap`/`expect` on values that carry text are forbidden; panics carry only static messages. Verify: unit test formats each type with `{:?}`/`{}` and asserts the content is absent; reviewer greps `derive(Debug)` on text-holding structs.
- **SEC-3 No core dumps, no ptrace.** Threat: apport / systemd-coredump captures memory with keystrokes. Requirement: at startup, before opening any socket, the daemon calls `prctl(PR_SET_DUMPABLE, 0)` and `setrlimit(RLIMIT_CORE, 0)`; the unit sets `LimitCORE=0`. Verify: in the nested session `cat /proc/<pid>/status` shows the process non-dumpable (`/proc/<pid>/` owned by root, or `prctl(PR_GET_DUMPABLE)` test); `kill -SEGV <pid>` produces no file in `/var/crash` and no entry in `coredumpctl list`.
- **SEC-4 Minimal retention in memory.** Threat: old words / passwords linger in heap. Requirement: the word buffer and surrounding text are cleared (zeroized, e.g. `zeroize`) on commit, reset, focus-out and IC destroy; no history beyond the current word; surrounding text is not requested unless the engine uses it and is dropped on focus-out. Verify: unit tests assert buffers are empty after each boundary event; reviewer checks no `Vec`/`String` of past words exists.
- **SEC-5 Persisted state is the mode only.** Requirement: the only file the daemon writes is the VI/EN state under `~/.local/state/vr-talex/` (dir 0700, file 0600, written atomically). Verify: after the stress test, `find ~/.local/state/vr-talex ~/.config/vr-talex ~/.cache/vr-talex -type f` lists only that file; content is `VI` or `EN`; `stat` shows modes.
- **SEC-6 Filesystem socket, never abstract.** Threat: abstract unix sockets have no file permissions and are reachable from other users and Flatpak sandboxes sharing the network namespace. Requirement: the private bus listens on a path socket `$XDG_RUNTIME_DIR/vr-talex/bus` (dir 0700, socket 0600, owned by the user); the address written for clients is `unix:path=…`; never `unix:abstract=`, `unix:tmpdir=`, TCP or `/tmp`. Verify: `ss -xlp | grep vr-talex` shows a path, no `@` entry; `stat` shows modes 0700/0600; reviewer checks the listen address code.
- **SEC-7 Safe address file and socket creation.** Requirement: the IBus address file (`~/.config/ibus/bus/<machine-id>-unix-<display>`) and the socket dir are created with `O_NOFOLLOW`/no-symlink checks, owner = current uid verified, mode 0600 (dir 0700); the address file is written to a temp file in the same dir and `rename`d; a stale socket is removed only if it is a socket owned by the user. If the address file pre-existed (real ibus), its original is backed up by install (SEC-21). Verify: test with a planted symlink at the address-file path → daemon refuses and logs a static error; `stat` checks; reviewer reads the creation code.
- **SEC-8 Peer authentication.** Requirement: the D-Bus server accepts only the `EXTERNAL` mechanism and rejects connections whose peer UID (`SO_PEERCRED`) differs from the daemon's UID; `ANONYMOUS` and `DBUS_COOKIE_SHA1` are disabled. The XIM server is reachable only through the user's X display (no extra listener). Verify: integration test connects with ANONYMOUS → rejected; unit test of the UID check with an injected foreign uid → rejected; reviewer checks server builder config.
- **SEC-9 Per-connection isolation of input contexts.** Threat: IDOR on IC object paths / XIM IC ids; broadcast signals. Requirement: every IC (IBus object path, XIM im-id/ic-id) records its owning connection (D-Bus unique peer / XIM client window); any method call or XIM request from another connection on that IC is rejected with an error. `CommitText`, `UpdatePreeditText`, `ForwardKeyEvent`, `DeleteSurroundingText` etc. are sent only to the owning connection (unicast / destination set), never broadcast. IC paths are not guessable sequentially across clients or, if sequential, the ownership check is mandatory. Verify: integration test with two connections: B calling `ProcessKeyEvent`/`FocusIn`/`Destroy` on A's IC → error; B never receives a signal for A's commit; same test for two XIM clients.
- **SEC-10 Panel role.** Requirement: only one Panel connection is accepted; the panel receives only what gnome-shell needs (mode label, preedit of the focused IC if the panel protocol requires it) and nothing for ICs whose content purpose is password/PIN. Verify: integration test: a second panel registration is rejected or replaces the first only via explicit documented rule; panel receives no preedit for a password IC.
- **SEC-11 Minimal bus surface.** Requirement: implement only the IBus methods gnome-shell and the GTK/Qt modules need; `Exit` (if implemented) exits cleanly and is restarted by systemd (SEC-17); `SetGlobalEngine` accepts only the vr-talex engine name; no extra debug/eval/dump methods on any interface; introspection does not expose internal state. Verify: reviewer lists the exported methods against the plan's list; test calling unknown methods → `UnknownMethod`.
- **SEC-12 Password/PIN passthrough.** Requirement: when an IC's content type purpose is PASSWORD or PIN (IBus `InputPurpose` 8/9), or hints include a private/sensitive-data hint, the engine returns every key "not handled" with no preedit, no buffering and no copy of the key in engine state; Ctrl+Shift toggle still works but leaves no trace. Verify: AC-7 (`matkhau1s` → exactly `matkhau1s`) in GTK entry with `visibility=false`, Chrome password input, and the gnome-shell lock-screen / polkit password dialog in the nested session; unit test asserts the buffer stays empty while purpose=password.
- **SEC-13 Content-type and focus transitions.** Requirement: on focus-out, focus change, or `SetContentType` switching a field to password/PIN, any pending preedit is committed to the IC it belongs to (B3) before the new state applies; text is never committed to a different IC than the one where it was composed. Verify: test: type `vieet`, then switch focus (or content type to password) → `viê` committed to the first field only, password field receives only its own keys.
- **SEC-14 XIM password residual risk.** Requirement: XIM carries no content purpose, so for XIM clients the daemon honours focus/IC destruction the client does around password fields and the plan documents the residual risk (X11 apps may get Telex in password fields); in addition the Ctrl+Shift toggle to EN must fully bypass the engine. Verify: qc tests Chrome (XWayland) login form password field; result recorded in the QA report as pass or known limitation; reviewer checks the limitation is in the README.
- **SEC-15 Robust parsing of untrusted messages.** Requirement: XIM and D-Bus message decoding validates every length/count against the remaining buffer and a hard cap before allocating; invalid UTF-8 and unknown opcodes produce an error reply or drop the client, never a panic; a failing client is disconnected without affecting others. Verify: unit/property tests feed truncated, oversized and random XIM packets (e.g. `proptest`) to the decoder → no panic; reviewer checks there is no `[..]` indexing or `unwrap` on wire data; one malicious-client test confirms other clients keep typing.
- **SEC-16 Resource caps.** Requirement: caps on connections (e.g. 256), ICs per connection (e.g. 64), preedit length (word > 32 chars is committed and passed through), surrounding text (e.g. 4 KiB, truncated), XIM message size (e.g. 64 KiB). Verify: tests exceed each cap → bounded memory and a clean error; values stated in the plan.
- **SEC-17 Crash recovery.** Requirement: the unit uses `Restart=always`, `RestartSec≤1s` and no start limit and a capped back-off (`StartLimitIntervalSec=0`, `RestartSteps=4`, `RestartMaxDelaySec=15`, FR-5) so the user is never locked out permanently; on restart the address file is rewritten atomically. A panic in any connection handler must not kill the key loop of others (no `panic=abort` hiding this; handlers isolated). Verify: nested session: `kill -SEGV` the daemon while typing in gnome-terminal and a GTK app → plain typing continues (Mutter/clients fall back to raw keys) and Vietnamese works again within 3 s; `systemctl --user status vr-talex` shows active.
- **SEC-18 Hang protection.** Requirement: `ProcessKeyEvent` is answered within a bound (e.g. 50 ms, else return "not handled"); the unit sets `WatchdogSec=` and the key loop pings `sd_notify WATCHDOG=1`, so a hung daemon is killed and restarted. Verify: test build with an injected stall → systemd restarts it within the watchdog interval and keys reach the app unprocessed meanwhile.
- **SEC-19 Never lock the user out.** Requirement: install writes the input sources just before starting the daemon (so the running shell selects Vietnamese (Telex) when it connects, FR-9); gnome-shell drops an IBus source whose engine no connected bus lists, so it cannot become current while the daemon is not answering; if the daemon is not healthy within a timeout, install rolls the sources and files back exactly (SEC-21) and exits non-zero. A recovery path that needs no typing in VI mode exists and is printed by install: `systemctl --user disable --now vr-talex` + `./uninstall.sh`; the lock-screen unlock works with the daemon stopped. Verify: test with a deliberately broken binary → install rolls back, sources unchanged; nested session lock/unlock with the daemon stopped and running.
- **SEC-20 No privilege.** Requirement: both scripts refuse to run as root (`[ "$(id -u)" -eq 0 ] && exit 1`), never call `sudo`/`pkexec`, write only under `$HOME` (`~/.local`, `~/.config`, `~/.local/state`) and use `systemctl --user` / `gsettings` only. Verify: `grep -nE 'sudo|pkexec|/etc/|/usr/' install.sh uninstall.sh` → none outside comments; run as root in a container → exits 1 with no changes.
- **SEC-21 Backup once, restore exactly.** Requirement: on first install the script saves the previous state to `~/.local/state/vr-talex/backup/` (0700): `input-sources sources`, `current`/`mru-sources`, fcitx5/ibus autostart and systemd user unit state, pre-existing IBus address files, any environment file it changes; a second install does not overwrite this backup. Uninstall restores exactly those values, re-enables and starts the previous framework, removes only what install created, then deletes the backup. Verify: AC-5/AC-6 in the nested session: snapshot (`gsettings list-recursively org.gnome.desktop.input-sources`, `systemctl --user list-unit-files`, `ls ~/.config/autostart ~/.config/environment.d`) before install, after install ×2 (identical), after uninstall (identical to the first snapshot).
- **SEC-22 Idempotent, scoped edits.** Requirement: install adds the Vietnamese source only if absent (exactly once); IM env vars go into a dedicated file (`~/.config/environment.d/90-vr-talex.conf`) and `systemctl --user set-environment`, not into `~/.profile`/`~/.bashrc`; if a shared file must be edited, only a marked block is added/removed. fcitx5/ibus are stopped via `systemctl --user` / autostart `Hidden=true` override files, not by deleting their files. Verify: run install twice → `diff` of snapshots empty; uninstall leaves no `vr-talex` string in `~/.config`, `~/.local` (except the git checkout).
- **SEC-23 Shell script hygiene.** Requirement: `set -euo pipefail`; every variable expansion quoted; every `rm -rf` target is a fixed literal path under `$HOME` built from a non-empty checked variable (`: "${HOME:?}"`); no `pkill`/`killall`/`pkill -f` — processes are stopped through `systemctl --user` or a PID the script recorded; `shellcheck` clean. Verify: `shellcheck install.sh uninstall.sh` → 0 warnings; reviewer reads every `rm`, `kill` and `gsettings set`.
- **SEC-24 No remote code at install.** Requirement: install uses only the local checkout and the local toolchain (`cargo build --release --locked --offline` allowed after a fetch step that uses `Cargo.lock`); no `curl|bash`, no `wget`, no rustup self-install, no binary downloads. If cargo is missing, install exits with a message. Verify: `grep -nE 'curl|wget|\| *(ba)?sh' install.sh` → none.
- **SEC-25 Locked, audited dependencies.** Requirement: `Cargo.lock` is committed; builds use `--locked`; `cargo audit` reports no unfixed advisory and `cargo deny check` passes with `advisories`, `bans` (no duplicate major versions where avoidable, no `openssl`/network crates), `sources` (crates.io only — no git or path deps from outside the repo) and `licenses` (allowlist). Every new crate is justified in the plan. Verify: CI/qc runs `cargo audit` and `cargo deny check` (via `run-heavy.sh`) → 0 errors; reviewer checks `deny.toml` and the lockfile diff on each dependency change.
- **SEC-26 Minimal, reputable crate set.** Requirement: direct dependencies limited to well-known pure-Rust crates (e.g. `zbus`, `x11rb`, `rustix`/`nix`, `zeroize`, `sd-notify`); no crate with a `build.rs` that touches the network or files outside `OUT_DIR`; no crate that enables networking at runtime. Verify: `cargo tree -e normal --depth 1` reviewed against the plan's list; reviewer greps new deps' `build.rs` on each manifest change.
- **SEC-27 No unsafe outside one audited module.** Requirement: every crate root has `#![forbid(unsafe_code)]` except at most one small `sys` module (prctl/rlimit if not covered by a safe crate) with `// SAFETY:` comments; wire parsing contains no `unsafe`. Verify: `grep -rn 'unsafe' src/` lists only that module; reviewer reads it.
- **SEC-28 No network, hardened unit.** Requirement: the daemon opens only AF_UNIX sockets (private bus, X11). The user unit sets at least `NoNewPrivileges=yes`, `UMask=0077`, `LimitCORE=0`, `RestrictAddressFamilies=AF_UNIX`, `IPAddressDeny=any`, `MemoryDenyWriteExecute=yes`, `LockPersonality=yes` (where the user manager supports them), and `ExecStart=%h/.local/bin/vr-talex` (absolute path, binary 0755 owned by the user, not group/world-writable). Verify: `systemd-analyze --user security vr-talex.service` output attached; `ss -tunap | grep vr-talex` → empty; `stat ~/.local/bin/vr-talex`.
- **SEC-29 Tests never touch the live desktop (D2).** Requirement: every automated integration/E2E test runs in a nested/headless GNOME Shell with its own `DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`, `HOME`/`XDG_CONFIG_HOME`; the harness aborts if those equal the live values; no test runs `install.sh` against the real `$HOME`. Verify: harness has a guard test; qc confirms the user's live fcitx5 PID and `gsettings get org.gnome.desktop.input-sources sources` are unchanged after the test run.

## Residual risks (accepted, documented in README)
- Any same-user process can already read keystrokes on X11 (XRecord/XInput2); vr-talex does not add isolation the X server lacks.
- Flatpak apps: with a path socket (SEC-6) they get no Vietnamese input unless an IBus portal (`org.freedesktop.portal.IBus`) is added later; if added, it must expose only InputContext creation and the IC methods with SEC-9/SEC-12 checks, never bus-level methods.
- Flatpak apps via the fcitx portal name (added after Phase 5, D29): fe-fcitx owns `org.freedesktop.portal.Fcitx`, which Flatpak's default policy lets sandboxed apps call. Such an app can create its own input context, toggle the global VI/EN mode with a Ctrl+Shift tap and observe the mode; it cannot read other contexts' text (per-connection context table, unicast signals, SEC-9). Accepted.
- XIM password fields (SEC-14) — moot since XIM was dropped (D19).
